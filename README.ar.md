# super-token-saver

**الإضافة الوحيدة لـ Claude Code التي تقرأ فعلاً الكود المصدري لـ CC لتكشف أين تذهب رموزك — وتُصلح ذلك تلقائياً. أنفق أقل، اعمل أطول.**

> نتيجة مقاسة: **خفض التكلفة بنسبة 45%** على عبء عمل حقيقي بقيمة $326/يوم → $180/يوم. تفويض SubTask تلقائي، استعادة السياق بدون تكلفة، لوحة تحليل متكاملة، وحارس لانتهاء صلاحية الكاش — في تثبيت واحد، بدون إعداد.

يعمل مع **Max Plan (‏$200/شهر)** و**API بالدفع حسب الاستخدام**. نفس الإضافة، نفس الميزات. أقوى لكل مستخدم — خاصةً حين يكون كل رمز مالاً حقيقياً.

![لوحة الاستخدام — اعرف بالضبط أين تذهب رموزك](docs/images/usage-view-overview.png)

## 😤 المشكلة

**تكاليف غير مرئية.** لا رؤية في الوقت الفعلي. لا تحذير "سياقك عند 800K". لا تنبيه "انتهى الكاش منذ 3 دقائق". تكتشف الضرر بعد أن يقع.

**انتفاخ السياق.** نفس الطلب عند سياق 200K مقابل 800K يكلّف 4 أضعاف. كل Read وGrep وEdit يُعيد إرسال السياق الكامل. طلب واحد معقد يُطلق 15+ استدعاء API، وكل واحد مضروب في حجم سياقك.

**انتهاء صلاحية الكاش.** عُدت من الغداء. الكاش اختفى. رسالة واحدة تُعيد إرسال 900K رمز بالسعر الكامل. $9 في ضربة واحدة.

**كل شيء يدوي.** إدارة السياق، توقيت انتهاء الكاش، تفويض SubTask، تنظيف الجلسات. لا أحد يستطيع تتبع كل هذا بينما يكتب الكود فعلاً.

**Max Plan (‏$200/شهر)?** كل ما سبق، إضافةً إلى حد المعدل لنافذة 5 ساعات الذي يوقف عملك بدون مؤقت وبدون وقت متوقع للانتهاء.

**API بالدفع حسب الاستخدام?** كل ما سبق، لكن بدون سقف. خطأ كاش واحد = $9 من أموال حقيقية. عشر مرات في الأسبوع = $360/شهر على الأخطاء وحدها. يوم ثلاثاء سيئ مع سياق منتفخ قد يكلّف أكثر مما يدفعه مشترك Max Plan في شهر.

super-token-saver يتعامل مع كل هذا تلقائياً. **ثبّته مرة واحدة. انتهى الأمر.**

## 🧠 الميزة 1: Smart Session Architecture

**ثبّته وأنماط العمل الموفِّرة للتكاليف تنطلق تلقائياً.**

معظم المستخدمين يعملون كل شيء في الجلسة الرئيسية. قراءة ملفات، توليد كود، تشغيل اختبارات. كل مخرج يتراكم في السياق ويُعاد إرساله مع كل رسالة. الجلسة تنتفخ. التكاليف تتضاعف.

Session Architect يحقن استراتيجية تفويض تلقائياً عند بدء الجلسة.

|                  | Main Session                      | SubTask                               |
| ---------------- | --------------------------------- | ------------------------------------- |
| الدور            | التصميم، القرارات، المراجعة       | التنفيذ، توليد الكود، ملفات متعددة   |
| مستوى الكاش      | ساعة (ephemeral_1h)               | 5 دقائق                               |
| تكلفة كتابة الكاش | ＄10/MTok                         | ＄6.25/MTok                            |
| حجم السياق       | ~94K متوسط                        | ~33K متوسط                            |

SubTasks لديها **كتابة كاش أرخص بنسبة 37.5%** من Main. السياق أصغر بكثير أيضاً. تفويض العمل الثقيل لـSubTasks يخفّض التكاليف بشكل كبير.

**النتيجة:** السياق يبقى تحت 250K بدلاً من أن ينمو إلى 600K+. نفس المخرجات، نصف تكلفة الرموز. تلقائي بالكامل.

## 🪶 Concise Mode

**نفس المحتوى. حشو أقل. مفعّل افتراضياً.**

خطاف SessionStart يحقن أيضاً قاعدة أسلوب الرد التي تعمل في **كل جلسة ومع كل نموذج** — بدون أعلام، بدون إعداد. ثلاثة أشياء تتغير:

- **لا مقدمات** — لا "دعني أتحقق…"، لا "سأقوم الآن…"، لا إعادة لسؤالك، لا تلخيص لما يظهره الـdiff أصلاً
- **التنسيق المناسب للمحتوى** — نقاط للقوائم، نثر للاستدلال (المقايضات، السببية، المبررات). لا شيء يُفرض
- **تعبير أكثر إيجازاً** — نفس الفكرة، كلمات أقل. النثر الأوضح هو النثر الأقصر

حد صارم: لا حذف محتوى، لا تخطي تحقق، لا تكثيف للدقائق في جملة واحدة. المادة تبقى كاملة؛ فقط الغلاف يصغر.

ثبّته مرة، يُطبَّق في كل مكان.

## 🔄 الميزة 2: /s-continue — استعادة السياق

**يستبدل `/compact`. صفر استدعاءات LLM. صفر تكلفة رموز. صفر فقدان معلومات.**

`/compact` يُرسل سياقك كاملاً (~1M رمز) إلى الـLLM لضغطه في ملخص بنسبة 3.3%. إذا انتهى صلاحية الكاش، هذا وحده يُطلق إعادة كاش كاملة. فقدان المعلومات حتمي.

`/s-continue` يتبع نهجاً مختلفاً كلياً. يعالج سجل الجلسة السابقة مسبقاً ويحمّله مباشرةً. لا استدعاء LLM. لا تكلفة. المحادثة الأصلية تُستعاد كما هي.

|                         | /compact                                    | /s-continue                                   |
| ----------------------- | ------------------------------------------- | ------------------------------------------- |
| طريقة العمل             | يُرسل السياق الكامل إلى LLM للتلخيص        | يعالج السجل مسبقاً ويقرأه مباشرةً          |
| استدعاءات LLM           | مطلوبة (عادةً 100K+ رمز)                   | 0                                           |
| تكلفة الرموز            | عالية                                       | 0                                           |
| فقدان المعلومات         | نعم (ملخص 3.3%)                             | لا (الأصل محفوظ)                            |
| سرعة المعالجة           | عشرات الثواني                               | أقل من ثانية (حتى ملفات 60MB+)             |
| عند انتهاء الكاش        | تكلفة إعادة الكاش الكاملة فوق ذلك          | لا تأثير                                    |
| استعادة جلسات متعددة   | غير ممكن                                    | مدعوم                                       |

الاستخدام: `/clear` ثم `/s-continue`. ستظهر قائمة بالجلسات السابقة. اختر التي تريد استعادتها. للاستعادة السريعة: `/s-continue last`.

**النتيجة:** استأنف العمل السابق بدون تكلفة. لا فقدان معلومات. يعالج سجلات 60MB+ في أقل من ثانية.

### 🤝 رفيقه: `/s-compact` — تسليم الطبقة الخفية

`/s-continue` يستعيد السجل — ما قلته أنت وClaude. لكن أهم معرفة في جلسة العمل غالباً ما تكون خارج ذلك الحوار: ما اكتشفه عميل فرعي (سجله ملف منفصل لا يحمّله الاستعادة أبداً)، رقم حاسم في مخرجات أداة (عدد اختبارات، قياس أداء)، أو درس مستفاد من العملية ("تعذّر إعادة الإنتاج بدون واجهة ← كانت المشكلة في البناء لا الكود").

شغّل `/s-compact` في نهاية الجلسة وسيُلخّص بالضبط تلك الطبقة الخفية إلى ملف تسليم، محفوظ في `~/.claude/super-token-saver-data/<project>/handoff.md`. في الجلسة التالية، يحمّله `/s-continue` تلقائياً فوق السجل المستعاد — بدون لصق.

|                     | `/s-continue` وحده              | `/s-compact` + `/s-continue` (الثنائي)          |
| يستعيد              | السجل (ما قيل)                   | السجل بالإضافة إلى الطبقة الخفية                 |
| نتائج العملاء الفرعيين | مفقودة (ملفات منفصلة)          | مُلخّصة في ملف التسليم                            |
| أرقام مخرجات الأدوات | فقط إن اقتُبست في المحادثة       | تُستخرج عمداً                                     |
| دروس العملية         | —                                | تُلتقط لتجنّب إعادة المسارات المسدودة             |

سير العمل: أنهِ الجلسة بـ `/s-compact` ← ابدأ التالية بـ `/s-continue`.

### 🔀 أداتان، سجل واحد — جلسات Codex تُستعاد هنا أيضاً

يكتب Codex جلساته في `~/.codex/sessions/`، بينما يكتب Claude Code في `~/.claude/projects/`. لا تقرأ أداة سجلات الأخرى. لذلك كانت مهمة توقفت في Codex بسبب نفاد الميزانية يتعذّر الوصول إليها من Claude Code، والعكس صحيح.

يعرض `/s-continue` الآن الجلستين ويستعيدهما معاً. لا يُسلَّم سجل Codex إلى محلّل ثانٍ — بل يُعاد كتابته بالشكل الذي يكتبه Claude Code، **سطر مخرج واحد لكل سطر مُدخل**، بحيث يخدم المسار نفسه الأداتين ويظل كل مؤشر `L{n}` يشير إلى السطر الفعلي في ملف Codex الأصلي. القياس الفعلي: يُعالَج سجل بحجم 12 MB و1,540 سطراً في **0.13 s**.

|                        | جلسة Claude Code | جلسة Codex |
| ---------------------- | ------------------- | ------------- |
| تظهر في `/s-continue` | نعم | نعم، ضمن نطاق المشروع الحالي |
| تُستعاد بتكلفة صفر لاستدعاءات LLM | نعم | نعم |
| البحث بـ `L{n}` في الأصل | نعم | نعم — أرقام الأسطر خاصة بالسجل نفسه |
| استعادة فقدان السياق (`#0`) | `/compact`، auto-compact | ضغط Codex الخاص واستعادة الخيط |
| ملف تسليم `/s-compact` | مشترك لكل مشروع — اكتبه في أداة واحدة، وحمّله في الأخرى |

```
/s-continue codex                    جلسات Codex فقط
/s-continue codex : rust migration   الأدوار المطابقة لموضوع معيّن، مُستعادة كاملةً
```

تفصيلان يفرّقان بين قائمة صحيحة وأخرى تبدو صحيحة لكنها خاطئة: مُعرِّف `session_id` في Codex هو معرّف **الخيط (thread)**، وهو ما يرثه أي عميل فرعي يُشغَّل داخله، لذلك تُفهرَس الجلسات بحسب `payload.id` وتُستبعد سجلات العملاء الفرعيين بنفس الطريقة التي تُستبعد بها سجلات المهام الفرعية في Claude Code. أما `<codex_internal_context source="goal">` فهو مُدرَج آلياً، لذا يبقى ضمن السياق المُستعاد لكنه لا يُحتسب أبداً كدور كتبته أنت.

الإضافة تُثبَّت أيضاً داخل Codex — راجع **[README-CODEX.md](./README-CODEX.md)** ([한국어](./README-CODEX.ko.md) · [日本語](./README-CODEX.ja.md) · [简体中文](./README-CODEX.zh-Hans.md)). تبقى `usage-view` و`report-limit` و`setup-statusline` حصرية لـClaude Code حالياً.

## 📊 الميزة 3: شريط الحالة المباشر

**مراقبة الرموز/التكاليف في الوقت الفعلي. أقل من 50ms تأخير.**

شغّل `/setup-statusline install` مرة واحدة وسيظهر شريط حالة دائم في أسفل Claude Code.

**التشغيل الطبيعي** — كل مقياس بنظرة، بدون تبديل السياق:

![شريط الحالة في الوضع الطبيعي](docs/images/statusline-normal.png)

**عند الوصول لحد المعدل** — 5H يتحوّل للأحمر عند 102%، العدّ التنازلي يُظهر بالضبط متى تعود، وإجراء `/report-limit` يظهر تلقائياً بنقرة واحدة:

![شريط الحالة عند الوصول لحد المعدل](docs/images/statusline-rate-limited.png)

| المؤشر           | ما يُظهره                                  | 🟢 طبيعي | 🟡 تحذير | 🔴 حرج   |
| ---------------- | ------------------------------------------ | --------- | --------- | --------- |
| RUN (دلتا)       | تكلفة آخر استدعاء API                      | < ＄0.30   | >= ＄0.30  | >= ＄1.00  |
| RUN (تراكمي)     | التكلفة التراكمية لهذا المجلد              | —         | —         | —         |

**النتيجة:** كل مشكلة في التكاليف مرئية في الوقت الفعلي. أقل من 50ms تأخير — لا تأخير ملحوظ.

> **تستخدم API بالدفع حسب الاستخدام?** مؤشرات 5H وW تُخفى تلقائياً — ليس لديك نوافذ حد المعدل. ما يبقى هو ما يهم: RUN (التكلفة الفورية لكل دور) وCTX (حجم السياق). الرافعتان اللتان تتحكمان في فاتورتك، دائماً مرئيتان.

## 📈 لوحة الاستخدام (/usage-view)

**أجب أخيراً: "أين ذهبت كل تلك الأموال؟"**

مستخدمو Max Plan يصلون لحد المعدل ويتساءلون لماذا. مستخدمو API يفتحون فاتورة Anthropic ويتساءلون كيف. في كلتا الحالتين، السؤال واحد: أي جلسة أحرقت أكثر الرموز؟ متى ارتفعت التكاليف فجأة؟ ما الأنماط في استخدامك؟ حتى الآن — كل هذا كان غير مرئي.

`/usage-view` يُظهر كل شيء. لوحة HTML تفاعلية تفتح في متصفحك، تتيح لك تحليل أنماط الاستخدام وتتبع السبب الجذري لارتفاعات التكلفة. بدون تبعيات خارجية. تعمل بشكل مستقل. قابلة للمشاركة كملف.

**$4,196 في 31 يوماً. أين ذهبت؟** نظرة واحدة — التكلفة الإجمالية، تفصيل الرموز بالنوع، نسبة كفاءة الكاش، وعدد الجلسات. المخطط الدائري يُظهر فوراً أن 65% من إنفاقك هو قراءات من الكاش (وهذا طبيعي وصحي):

![نظرة عامة على لوحة الاستخدام](docs/images/usage-view-overview.png)

**قبل وبعد — مقيس، لا مخمَّن.** علامة "Plugin installed" البرتقالية المنقطة تقسم جدول التكاليف الزمني إلى قسمين. الأعمدة اليومية مقسَّمة بنوع الرمز (Input/Output/Cache Write/Cache Read) لترى بالضبط أي مكون تغيّر بعد التثبيت. خط المتوسط يُظهر الاتجاه:

![اتجاه التكاليف اليومية](docs/images/usage-view-daily-trend.png)

**متى تُنفق الأكثر؟** التكلفة بالساعة حسب وقت اليوم وتفصيل حسب يوم الأسبوع. التبديل بين متوسط اليوم النشط، متوسط اليوم الكامل، أو الحد الأقصى. أيقونات النار تُميّز ساعاتك الأغلى — الأنماط الواضحة (السهرات الليلية، ارتفاعات الأربعاء) تظهر فوراً:

![نمط التكلفة بالساعة وحسب يوم الأسبوع](docs/images/usage-view-hourly-pattern.png)

**هل تصبح أكثر كفاءة؟** نسبة Total/Output تقيس كم رمزاً يُستهلك لكل رمز مخرج منتَج. الأقل أفضل. علامة "Plugin installed" تتيح لك المقارنة قبل وبعد. الارتفاعات = أخطاء كاش أو إعادة تشغيل جلسات:

![اتجاه الكفاءة](docs/images/usage-view-efficiency.png)

**كل استدعاء API، مرسوم بحجم السياق والتكلفة.** هذا هو المخطط الذي يوضح بنية التكاليف. كل نقطة هي استدعاء API واحد. أحمر = Opus، أزرق = Sonnet، أخضر = Haiku. الخطوط المنقطة هي الأسعار النظرية — إذا كانت نقاطك فوق الخط، أنت تدفع أكثر من اللازم. التبديل إلى عرض **User Turn** لرؤية التكلفة لكل دور في المحادثة بدلاً من كل استدعاء API.

## ✂️ الميزة 4: /setup-git-lite — تقليم تعليمات git المدمجة في CC

**قرأنا الكود المصدري لـClaude Code. وجدنا 2,200 رمز خفي تُحقن في كل جلسة وأنت تدفعها بصمت.**

### الاكتشاف

في 2026-04-12، كشف [إشكال GitHub](https://github.com/anthropics/claude-code/issues/47107) أن إعداد `includeGitInstructions` المدمج في Claude Code يحرق الرموز بصمت في كل جلسة. التحقق المستقل عبر [هذا gist (spilist)](https://gist.github.com/spilist/b0db92a859192f5ec6199d3f35a81b98) أكد الأرقام: **+6,031 رمزاً في كتابات الكاش** لكل جلسة بعد كل git commit، **+1,690 رمزاً في قراءات الكاش** في كل استدعاء API.

### تحليل كود CC المصدري — أين تذهب الرموز

تتبعنا الرموز إلى نقطتَي حقن مستقلتين في كود Claude Code المصدري (v2.1.88):

**1. لقطة `gitStatus` (~500 رمز) — الطلب النظامي**
- `context.ts:36-111` تقوم `getGitStatus()` بجمع الفرع + الفرع الرئيسي + user.name + الحالة الكاملة (حتى 2000 حرف) + **آخر 5 commits**
- تُدمج وتُضاف للطلب النظامي عبر `appendSystemContext` (‏`utils/api.ts:437`)
- كل commit جديد، كل ملف معدَّل جديد، كل تبديل فرع يغيّر النص → إلغاء صلاحية كاش البادئة

**2. تعليمات سير عمل Commit/PR (~1,700 رمز) — وصف أداة Bash**
- `tools/BashTool/prompt.ts:53` يُضيف 60+ سطراً من بروتوكول الأمان، إجراء commit خطوة بخطوة، أمثلة HEREDOC، وقوالب إنشاء PR إلى وصف أداة `Bash`
- مُخزَّن في الكاش مع الطلب النظامي، لكنه مُرسَل كمعامل `tools[]`

### لماذا هذا مكلف

بنية الكاش (‏`utils/api.ts:321` `splitSysPromptPrefix`) لديها ثلاثة مسارات بناءً على وجود أدوات MCP نشطة:

- **المسار A** (MCP نشط — معظم المستخدمين): `gitStatus` داخل كتلة `cacheScope: 'org'`. أي تغيير → إعادة تخزين الكتلة كاملة عند بدء الجلسة التالية → خطأ `cache_create` بـ6K رمز.
- **المسار B** (بدون MCP): `gitStatus` يذهب لكتلة ديناميكية `cacheScope: null`، مما يعني إعادة إرساله كـ`input_tokens` جديدة في كل استدعاء API — لا خطأ كاش، لكن لا توفير في الكاش أيضاً.
- **المسار C** (مزوّد خارجي / بيتا تجريبية معطّلة): كالمسار A.

في الجلسات التفاعلية النموذجية، تعليمات commit/PR (1.7K رمز) تتراكم **في كل استدعاء API** عبر `cache_read`. في جلسة بـ100 استدعاء بأسعار Opus 4.7، ذلك يعني تقريباً **$0.08 لكل جلسة** فقط لتعليمات يغطيها تدريب Claude في معظمه.

### كيف يعالج super-token-saver ذلك

`/setup-git-lite` يعطّل المسار الأصلي ويحقن **بديلاً مُختاراً بعناية من 280 رمزاً** عبر خطاف SessionStart. أبقينا بالضبط ما يتجاوز السلوك الافتراضي لـClaude (قواعد الأمان)، وحذفنا كل ما يعرفه Claude من التدريب (سير العمل خطوة بخطوة، قوالب PR، أنماط استخدام gh).

**مُحتفَظ به — 11 قاعدة تجاوز حرجة** (تلك التي تحوّل مساعدة Claude الافتراضية إلى حذر):
- لا commit/push/amend/PR/tag/merge دون طلب صريح من المستخدم
- لا تخطي خطافات، لا force-push لـmain/master، لا تشغيل عمليات مدمِّرة، لا تعديل git config
- لا commit لملفات تطابق `.env`، `credentials`، `*.pem`، `secret.*`
- تجنّب `git add -A` / `git add .`
- HEREDOC لرسائل commit متعددة الأسطر + تذييل `Co-Authored-By: Claude`
- لا أعلام تفاعلية (-i)، لا commits فارغة
- إذا فشل خطاف pre-commit → أنشئ commit جديداً (ليس `--amend`)

**محذوف** — سير عمل commit خطوة بخطوة (3 خطوات)، سير عمل PR خطوة بخطوة (3 خطوات)، قالب عنوان/نص PR، مراجع أوامر `gh`، تحذير علم `-uall`، تحذير `--no-edit` مع rebase، قيد `NEVER use TodoWrite or Agent tools during commit`. هذا تفصيل مسار عمل يُركّبه Claude بشكل صحيح من التدريب وحده.

**مُضاف** — سطر حالة git مضغوط: الفرع + SHA مختصر لـHEAD + الموضوع + الحالة الحالية (حتى 20 ملفاً معدَّلاً، وإلا عدداً). لا قائمة commits حديثة (Claude يستطيع تشغيل `git log` عند الطلب).

### التوفير المتوقع (أسعار Opus 4.7، $25/MTok مخرجات، $5/MTok مدخلات، $0.50/MTok قراءة كاش)

| العنصر | الأصلي | مع setup-git-lite | الموفَّر |
| ------- | ------- | ----------------- | -------- |
| تحميل الطلب النظامي (لكل جلسة جديدة) | ~2,200 رمز cache_create | ~280 رمز cache_create | ~1,920 رمز |
| الاستدعاءات المتكررة في نفس الجلسة | ~1,700 رمز cache_read/استدعاء | ~280 رمز cache_read/استدعاء | ~1,420 رمز/استدعاء |
| جلسة بـ100 استدعاء (Opus 4.7) | — | — | **~$0.11 موفَّرة** |
| 20 جلسة/يوم × 22 يوم عمل | — | — | **~$48 موفَّرة/شهر** |

### الاستخدام

```bash
/setup-git-lite status     # تشخيص للقراءة فقط — الحالة الحالية + ما سيتغير
/setup-git-lite install    # تعطيل CC native + تفعيل خطافنا الأدنى
/setup-git-lite revert     # استعادة الافتراضي (عدواني؛ انظر أدناه)
/setup-git-lite dismiss-banner    # إسكات تلميح التوصية العرضي
/setup-git-lite undismiss-banner  # إعادة تفعيل التلميح
/setup-git-lite help       # الاستخدام الكامل
```

### دلالات التثبيت

`install` يعدّل **موضعَين** للمتانة:

1. `~/.claude/settings.json` — يُضيف `"includeGitInstructions": false`
2. ملف تعريف الصدفة (`~/.zshrc`، `~/.bashrc`، إلخ) — يُلحق كتلة علامة تُصدِّر `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1`

أيٌّ منهما وحده كافٍ لتعطيل CC native؛ نضع كليهما حتى لا يُعيد تجاوز بيئي السلوك الأصلي عن طريق الخطأ. تغيير الصدفة يسري في الصدفات الجديدة فقط.

### دلالات الإعادة — عدواني

`revert` **يحذف جميع تصديرات `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS` من ملف تعريف صدفتك**، بما في ذلك تلك التي ربما أضفتها يدوياً قبل تثبيت هذه المهارة. هذا مقصود — أجريت `revert`، إذن نُعيد الافتراضي النظيف. نُنشئ دائماً نسخة احتياطية مختومة بالتوقيت لملف تعريف الصدفة.

إذا كنت تحتاج متغير البيئة لأسباب غير متعلقة، دوِّنه قبل تشغيل `revert` وأضفه مجدداً بعده.

### قبل إلغاء تثبيت super-token-saver

**شغّل `/setup-git-lite revert` أولاً**، وإلا ستبقى مع `includeGitInstructions: false` في settings.json لكن بدون خطاف بديل (Claude لن يحصل على أي توجيه git). لا يوجد حالياً في Claude Code خطاف دورة حياة لإلغاء تثبيت الإضافات، لذا لا يمكننا أتمتة ذلك.

### المقايضات

ما تخسره (ولماذا عادةً لا بأس بذلك):
- Claude لم يعد يتلقى `git status` / `git log -n 5` محسوبَين مسبقاً عند بدء الجلسة. إذا سألت "ما الذي تغيّر؟" في جلسة جديدة، سيُشغّل Claude تلك الأوامر بنفسه (استدعاء أداة واحد إضافي، ~300 رمز).
- Claude لم يعد يرى إجراء commit ثلاثي الخطوات لـCC. في اختباراتنا على مئات من تدفقات commit، المعرفة على مستوى التدريب تتعامل مع الحالات الحرجة (تنسيق HEREDOC، لا `--amend`، لا force-push) لأننا نُبقي هذه كقواعد صريحة.
- قالب نص PR (‏`## Summary` + `## Test plan`) لا يُحقن. إذا كنت تهتم بذلك التنسيق بالضبط، ضعه في CLAUDE.md الخاص بمشروعك.

### لافتة التوصية

حين تعليمات git الأصلية لـCC ما زالت نشطة على جهازك، يُظهر super-token-saver تلميحاً من فقرة واحدة عند بدء الجلسة **~20% من الوقت** (إضافةً إلى في مخرجات `/usage-view` و`/report-limit`). أسكته نهائياً بـ`/setup-git-lite dismiss-banner`.

## 🛡️ الميزة 5: Token Guardian

**يخبرك في اللحظة التي يكلّفك فيها انتهاء صلاحية الكاش. ويستطيع حجب إعادة الإرسال بـ$9 إذا طلبت منه ذلك.**

مدة صلاحية كاش طلبات Claude Code هي ساعة واحدة. ابتعد لأكثر من ساعة وسينتهي الكاش. رسالتك التالية ستُعيد إرسال السياق كاملاً بالسعر الكامل. عند 900K رمز، ذلك $9 في ضربة واحدة.

Token Guardian يتذكر وقت وصول آخر رد. إذا مرّت أكثر من 3,590 ثانية (مدة الصلاحية ناقص هامش أمان 10 ثوانٍ)، يمكنه أن يتدخل. **وهو معطّل افتراضياً، بسبب Remote Control (التحكم عن بُعد).** رسالة حجب الـhook تُعرض محلياً كرسالة نظام لا يستقبلها العميل البعيد أبداً، فرأى مستخدم بعيد الطلب يختفي بلا أي تفسير. وبدلاً من إطلاق حارس يتصرف بشكل مختلف حسب مكان جلوسك، عطّلناه. حين يبدأ Remote Control بتمرير رسائل الـhooks، سيعود الوضع الافتراضي إلى التفعيل. حتى ذلك الحين، فعّله بنفسك بأحد الوضعين التاليين.

```
export CC_TOKEN_SAVER_CACHE_GUARD=warn    # يذكر Claude انتهاء الصلاحية في أول سطر من رده
export CC_TOKEN_SAVER_CACHE_GUARD=block   # يُرفض الطلب مرة واحدة بالرسالة أدناه
```

في وضع warn يمر الطلب، ويبدأ Claude رده بسطر واحد يقول إن الكاش كان قد انتهى، وإن هذا الدور حُسب كإعادة إرسال كاملة للسياق، وإن المسار الأرخص بعد استراحة تبلغ ساعة أو أكثر هو `/clear` → `/s-continue`. هذا يصل فعلاً إلى العميل البعيد، لأن رد Claude يُمرَّر حتى لو لم تُمرَّر رسائل الـhooks.

في وضع block يُرفض الطلب مرة واحدة مع الرسالة أدناه. أعد إرساله وسيمر. استخدمه في طرفية محلية حين تريد الإيقاف الصارم.

```
🚨 Cache expired (68m 23s idle)

The prompt cache has expired. Continuing will resend the full context.
Cost may increase significantly.

👉 /context — Check current context usage before deciding
👉 /clear → /s-continue — Reset, then restore previous context (recommended, cheapest)
👉 Re-send — Continue as-is (full re-cache cost incurred)
```

رسالة الحجب تظهر بـ23 لغة بناءً على لغة نظامك، وتُطلق مرة واحدة فقط لكل فترة خمول.

**الوكلاء الخلفيون (background agents) لا يُحجبون أبداً.** الفحص يطال فقط ما يكتبه إنسان مباشرة. تقارير الإنجاز من الوكلاء والمهام الخلفية — التي أصبحت الآن تصل بشكل روتيني بعد أكثر من ساعة من إطلاقها — تمر مباشرة. نتيجة وكيل يعمل لفترة طويلة لا تُحجب أو تُفقد أبداً.

**النتيجة:** في وضع warn تعرف دائماً متى حدثت إعادة إرسال بـ$9، ولماذا. في وضع block لا تحدث أصلاً: كل انتهاء كاش يُكتشف = $9 موفَّرة، ومرة واحدة يومياً = $270/شهر من الهدر الصافي يُلغى.

> **إذا كنت تستخدم API بالدفع حسب الاستخدام، الأثر أشد.** مشتركو Max Plan يخسرون $9 ضمن هامش $200. أنت تخسر $9 من أموال حقيقية — بصمت، بتكرار، في كل مرة تبتعد. Token Guardian في وضع block يوقف ذلك في كل مرة.

## 💡 كيف يعمل الكاش فعلاً (ولماذا يهدر معظم المستخدمين 40%+ منه)

Claude Code يُرسل سجل المحادثة كاملاً إلى النموذج في كل استدعاء API. "استدعاء API" لا يعني "رسالة واحدة كتبتها". طلب واحد يُطلق استدعاءات أدوات داخلية — Grep وRead وEdit وWrite — وكل منها استدعاء API منفصل. طلب واحد يستطيع بسهولة إطلاق 10+ استدعاءات API.

كاش الطلبات يُقلّل هذه التكلفة بنسبة 90%. لكن الكاش له عمر.

|                     | Main Session                               | SubTask                                    |
| ------------------- | ------------------------------------------ | ------------------------------------------ |
| مدة صلاحية الكاش    | ساعة (ephemeral_1h)                        | 5 دقائق                                    |
| كتابة الكاش         | ＄10/MTok                                   | ＄6.25/MTok                                 |
| قراءة الكاش         | ＄0.50/MTok                                 | ＄0.50/MTok                                 |
| عند انتهاء الكاش    | السياق الكامل يُعاد إرساله بالسعر الكامل  | تأثير منخفض (السياق صغير)                 |

حتى مع الكاش الحي، التكاليف تتراكم. هذا سيناريو متطرف لإظهار الفرق.

### سيناريو: يوم عمل كامل (3 ساعات صباحاً → 2 ساعة غداء/اجتماع → 3 ساعات بعد الظهر)

الشروط: أسعار Opus 4، طلب واحد بالدقيقة، ~5 استدعاءات API لكل طلب (~300 استدعاء/ساعة).

#### ❌ بدون super-token-saver

معظم العمل يحدث في Main session. السياق ينمو بسرعة.

| المرحلة        | الوضع                              | حجم السياق                    | التكلفة                                   |
| -------------- | ---------------------------------- | ----------------------------- | ----------------------------------------- |
| صباح 3 ساعات   | البرمجة (معظمها في Main)           | 100K → 600K (متوسط 350K)     | 900 استدعاء × 350K × ＄0.50/M = ＄157.50   |
| غداء/اجتماع   | الغياب لساعتين                     | —                             | —                                         |
| العودة         | الكاش انتهى → إعادة إرسال كاملة   | 600K بالسعر الكامل           | 600K × ＄5/M + 600K × ＄10/M = ＄9          |
| العودة         | /compact (تلخيص)                   | 600K → يُرسل للـLLM          | 600K × ＄0.50/M + مخرجات الملخص = ~＄1.50  |
| بعد الظهر 3 ساعات | البرمجة تتواصل (السياق ينمو من جديد) | 100K → 600K (متوسط 350K) | 900 استدعاء × 350K × ＄0.50/M = ＄157.50 |
|                | الإجمالي                           |                               | ~＄326                                     |

> عند هذا المستوى من الاستخدام، ستصل على الأرجح لحد نافذة 5 ساعات. **التكلفة سيئة، لكن المشكلة الحقيقية هي توقف عملك كلياً. هذه بالضبط اللحظة التي يُظلم فيها Claude Code.**

#### ✅ مع super-token-saver

العمل الثقيل مفوَّض لـSubTasks. Main يتعامل مع التصميم/القرارات فقط.

| المرحلة        | الوضع                                           | حجم السياق                      | التكلفة                              |
| -------------- | ----------------------------------------------- | -------------------------------- | ------------------------------------ |
| صباح 3 ساعات   | البرمجة (Main: التصميم، SubTask: التنفيذ)       | Main 100K → 300K (متوسط 200K)  | 900 استدعاء × 200K × ＄0.50/M = ＄90  |
| غداء/اجتماع   | الغياب لساعتين                                  | —                                | —                                    |
| العودة         | ⚡ Token Guardian (وضع block) → /clear + /s-continue | —                                | ＄0 (لا استدعاءات LLM)               |
| بعد الظهر 3 ساعات | البرمجة تتواصل                              | Main 100K → 300K (متوسط 200K)  | 900 استدعاء × 200K × ＄0.50/M = ＄90  |
|                | الإجمالي                                        |                                  | ~＄180                                |

#### 💰 النتيجة

> **＄326 → ＄180. ＄146 موفَّرة يومياً. تخفيض التكلفة بنسبة 45%.**
>
> **Max Plan:** رموز أقل = لا تصل لحد المعدل. عملك لا يتوقف. هذا هو الفرق الحقيقي.
>
> **API بالدفع حسب الاستخدام:** ＄146/يوم × 22 يوم عمل = **＄3,200/شهر مباشرةً من فاتورتك.** شهر ثقيل بدون هذه الإضافة يتجاوز ＄7,000. معها، أقل من ＄4,000. نفس المخرجات.

### أين يتدخل super-token-saver

```
[بدء الجلسة]
    │
    ├─ Session Architect → يحقن تلقائياً نمط تفويض SubTask
    │                       يُبقي سياق Main تحت 250K
    │
[العمل]
    │
    ├─ Status Line → مراقبة التكلفة/السياق/حد المعدل في الوقت الفعلي

    │
[خمول أكثر من ساعة]

[إعادة تشغيل الجلسة]
    │
    └─ /s-continue → يستعيد السياق السابق بدون تكلفة (لا استدعاءات LLM)
```

- **skills/usage-view/** — تغييرات تصميم UI/UX للوحة

اجعله ملكك. فرِّعه، جرِّب، وأرسل PR إذا وجدت شيئاً أفضل.

## ⚖️ ما تكلّفك هذه الإضافة

الإضافة تحقن سياقاً عند بدء الجلسة. هذا بالضبط كم:

| الحقن | متى | الرموز | الغرض |
| ----- | ---- | ------ | ------ |
| Session Architect | SessionStart (مرة واحدة) | ~1,100 | استراتيجية تفويض SubTask + قواعد Concise Mode |
| سياق Git (إذا كان git-lite مفعّلاً) | SessionStart (مرة واحدة) | ~280 | يستبدل ~2,200 رمز من تعليمات git الأصلية لـCC |
| تحذير انتهاء الكاش | عند الخمول > 59 دقيقة (مرة واحدة) | ~200 | يُنبّه إلى إعادة الإرسال المكلفة، ويُظهر المسار الأرخص |
| شريط الحالة | كل استدعاء API | 0 | يُعرض في شريط حالة الطرفية، لا في سياق المحادثة |

**إجمالي التكلفة الإضافية لكل جلسة: ~1,400 رمز (لمرة واحدة، مُخزَّن في الكاش بعد أول استدعاء).**

بأسعار Opus ($0.50/MTok قراءة كاش)، ذلك **$0.0007 لكل استدعاء API** — أقل من عُشر سنت. في جلسة بـ100 استدعاء: $0.07.

إذا كان git-lite مفعَّلاً، الإضافة **تُوفِّر** ~1,920 رمزاً لكل جلسة (تستبدل 2,200 بـ280). الأثر الصافي سلبي — الإضافة تستهلك أقل مما تُزيل.

**لمستخدمي API بالدفع حسب الاستخدام:** عند إنفاق $3,000/شهر، تكلفة الإضافة الإضافية أقل من $2/شهر. إعادة إرسال $9 محجوبة واحدة في الأسبوع بسبب انتهاء الكاش تكفي لدفع تكلفة إضافية لسنة كاملة في اكتشاف واحد.

## 💡 نصائح

### افهم الكاش وسترى أين تذهب الأموال

- **1 طلب ≠ 1 استدعاء API.** في كل مرة يستدعي فيها Claude Grep أو Read أو Edit، يُعاد إرسال السياق كاملاً. طلب واحد يستطيع بسهولة إطلاق 10+ استدعاءات API. اكتب طلبات واضحة لتقليل استدعاءات الأدوات غير الضرورية وخفض التكاليف.
- **مؤقت الكاش يُعاد من آخر استدعاء API، لا من آخر طلبك.** استمر في العمل والكاش لن ينتهي أبداً. الخطر في الابتعاد. Token Guardian يخبرك حين يحدث ذلك، وفي وضع `block` يوقف الطلب مرة واحدة لتختار: إعادة ضبط السياق، أو الاستمرار كما هو.
- **حجم السياق = مضاعف التكلفة.** نفس استدعاء API عند 200K مقابل 800K يكلّف 4 أضعاف. حين يتجاوز [CTX] في شريط الحالة 35% (🟡)، هذه إشارتك لتفويض المزيد لـSubTasks.

### عادات تُخفِّض التكاليف

- **أبقِ CLAUDE.md خفيفاً.** يُحمَّل في الطلب النظامي في كل استدعاء API. كل سطر يكلّف مالاً.
- **فوِّض العمل الثقيل لـSubTasks.** توليد الكود، تحرير ملفات متعددة، تشغيل الاختبارات لا تنتمي لـMain. SubTasks لها سياق أصغر ومستوى كاش أرخص.
- **ستغيب لساعة أو أكثر?** `/clear` → عُد → `/s-continue`. السياق يُستعاد بـ$0.
- **[5H] فوق 70% (🟡)?** تباطأ. تحوّل لمهام مراجعة خفيفة أو زِد تفويض SubTask لتقليل عدد استدعاءات API من Main.
- **استخدم `/btw` للأسئلة الجانبية.** لا تدخل في سجل المحادثة، فسياقك يبقى خفيفاً.

### API بالدفع حسب الاستخدام: العادات الأكثر أهمية

كل ما سبق ينطبق، إضافةً إلى هذه الأولويات الخاصة بالAPI:

- **راقب [CTX] كعدّاد السرعة.** حد المعدل لن يوقفك — لكن سياق بـ500K+ يعني كل استدعاء API يكلّف 2-3 أضعاف ما يجب. `/clear` → `/s-continue` مجاني ويُعيد ضبط مضاعف التكلفة للأساس.
- **شغّل `/usage-view` أسبوعياً.** مستخدمو Max Plan لديهم لحظة "آخ" طبيعية حين يصلون لحد المعدل. أنت لا — التكاليف ترتفع بصمت. اللوحة نظام إنذارك المبكر.
- **حدِّد ميزانية يومية ذهنية.** بدون سقف، تحدث أيام بـ$200 دون أن تلاحظ. مؤشر RUN في شريط الحالة يجعل تكلفة كل دور مرئية. إذا تجاوز دور واحد $1 (🔴)، سياقك كبير جداً.
