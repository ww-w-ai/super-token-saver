**Единственный плагин для Claude Code, который действительно читает исходный код CC, чтобы найти, куда уходят ваши токены — и исправляет это автоматически. Тратьте меньше, работайте дольше.**

## 🧠 Функция 1: Smart Session Architecture

**Установите его — и паттерны работы с оптимизацией затрат начнут действовать автоматически.**

Большинство пользователей делают всё в основной сессии (Main session). Чтение файлов, генерация кода, запуск тестов. Каждый вывод накапливается в контексте и повторно отправляется с каждым сообщением. Сессия разбухает. Затраты растут лавинообразно.

Session Architect автоматически внедряет стратегию делегирования в начале сессии.

|                  | Main Session                      | SubTask                               |
| ---------------- | --------------------------------- | ------------------------------------- |
| Роль             | Проектирование, решения, проверка | Реализация, генерация кода, несколько файлов |
| Уровень кэша     | 1 час (ephemeral_1h)              | 5 мин                                 |
| Запись в кэш     | ＄10/MTok                          | ＄6.25/MTok                            |
| Размер контекста | ~94К ср.                          | ~33К ср.                              |

SubTask имеют **на 37,5% более дешёвую запись в кэш**, чем Main. Контекст также намного меньше. Делегирование тяжёлой работы в SubTask резко снижает затраты.

**Результат:** Контекст остаётся ниже 250К вместо роста до 600К+. Тот же объём работы, вдвое меньше токенов. Полностью автоматически.

## 🪶 Concise Mode

**То же содержание. Меньше лишнего. Включён по умолчанию.**

Хук SessionStart также внедряет правило стиля ответов, которое работает в **каждой сессии и для каждой модели** — без флагов, без настройки. Три вещи меняются:

- **Преамбула исчезает** — никакого «Позвольте проверить…», «Сейчас я…», повтора вашего вопроса или пересказа того, что уже показывает diff
- **Правильный формат для контента** — списки для перечислений, проза для рассуждений (компромиссы, причинно-следственные связи, обоснования). Ничто не навязывается
- **Более лаконичное выражение** — та же мысль, меньше слов. Более чёткая проза — более короткая проза

Жёсткое ограничение: никогда не пропускать содержание, не пропускать проверку и не сворачивать нюансы в одно предложение. Содержание остаётся полным; сжимается только обёртка.

Установите один раз — применяется везде.

## 🔄 Функция 2: /s-continue — Восстановление контекста

**Заменяет `/compact`. Ноль вызовов LLM. Ноль затрат на токены. Ноль потерь информации.**

`/compact` отправляет весь ваш контекст (~1М токенов) в LLM для сжатия в резюме 3,3%. Если кэш истёк, это само по себе запускает полное повторное кэширование. Потеря информации неизбежна.

`/s-continue` использует совершенно другой подход. Он предварительно обрабатывает транскрипт предыдущей сессии и загружает его напрямую. Без вызова LLM. Без затрат. Оригинальный разговор восстанавливается как есть.

|                             | /compact                                      | /s-continue                                   |
| --------------------------- | --------------------------------------------- | ------------------------------------------- |
| Как работает                | Отправляет полный контекст в LLM для резюме   | Предобрабатывает транскрипт, читает напрямую |
| Вызовы LLM                  | Требуются (обычно 100К+ токенов)              | 0                                           |
| Затраты на токены           | Высокие                                       | 0                                           |
| Потеря информации           | Да (резюме 3,3%)                              | Нет (оригинал сохранён)                     |
| Скорость обработки          | Десятки секунд                                | < 1 сек (даже файлы 60 МБ+)                |
| При истёкшем кэше           | Полная стоимость повторного кэширования сверху | Без влияния                                 |
| Восстановление нескольких сессий | Не поддерживается                        | Поддерживается                              |

Использование: `/clear`, затем `/s-continue`. Появится список предыдущих сессий. Выберите ту, которую хотите восстановить. Для быстрого восстановления: `/s-continue last`.

**Результат:** Возобновляйте предыдущую работу без затрат. Без потери информации. Обрабатывает транскрипты 60 МБ+ менее чем за 1 секунду.

### 🤝 Его пара: `/s-compact` — передача скрытого слоя

`/s-continue` восстанавливает транскрипт — то, что сказали вы и Claude. Но самое полезное знание рабочей сессии часто живёт ВНЕ этого диалога: что нашёл sub-agent (его транскрипт — отдельный файл, который восстановление никогда не загружает), решающее число в результате инструмента (количество тестов, бенчмарк), или урок, извлечённый из процесса ("не удалось воспроизвести в headless-режиме ← причина была в сборке, а не в коде").

Запустите `/s-compact` в конце сессии, и он дистиллирует именно этот скрытый слой в передачу дел, сохранённую в `~/.claude/super-token-saver-data/<project>/handoff.md`. В следующей сессии `/s-continue` автоматически загружает её поверх восстановленного транскрипта — без вставки вручную.

|                     | Только `/s-continue`            | `/s-compact` + `/s-continue` (пара)             |
| Восстанавливает     | Транскрипт (что было сказано)    | Транскрипт плюс скрытый слой                     |
| Находки sub-agent   | Теряются (отдельные файлы)       | Дистиллируются в передачу дел                     |
| Числа из вывода инструментов | Только если процитированы в чате | Извлекаются целенаправленно                |
| Уроки процесса      | —                                | Фиксируются, чтобы не повторять тупики            |

Рабочий процесс: завершите сессию через `/s-compact` → начните следующую через `/s-continue`.


### 🔀 Один инструмент историй на двоих — сессии Codex тоже восстанавливаются здесь

Codex пишет свои сессии в `~/.codex/sessions/`, Claude Code — в `~/.claude/projects/`. Ни один из них не читает файлы другого. Поэтому спринт, у которого в Codex закончился бюджет, был недоступен из Claude Code — и наоборот.

Теперь `/s-continue` показывает и восстанавливает сессии обоих инструментов. Rollout Codex не передаётся во второй парсер — он переписывается в тот же формат, в котором пишет Claude Code, **одна выходная строка на одну входную**, поэтому один и тот же пайплайн обслуживает оба инструмента, а каждая метка `L{n}` по-прежнему указывает на ту же строку исходного файла Codex. Измерено: rollout на 12 MB, 1,540-line, предобрабатывается за **0.13 s**.

|                              | Сессия Claude Code | Сессия Codex |
| ---------------------------- | -------------------- | -------------- |
| Показывается в `/s-continue` | Да | Да, только в рамках текущего проекта |
| Восстанавливается без затрат LLM | Да | Да |
| Переход по `L{n}` к оригиналу | Да | Да — номера строк берутся из самого rollout'а |
| Восстановление после потери контекста (`#0`) | `/compact`, авто-компакция | Компакция Codex и откат треда |
| Передача дел `/s-compact` | Общая на проект — запишите в одном инструменте, загрузите в другом |

```
/s-continue codex                    only Codex sessions
/s-continue codex : rust migration   the turns matching a topic, restored in full
```

Есть два нюанса, которые отделяют правильный список от правдоподобного, но неверного: `session_id` в Codex — это id **треда**, который наследует любой порождённый sub-agent, поэтому сессии индексируются по `payload.id`, а rollout'ы sub-agent'ов отфильтровываются так же, как Claude Code уже фильтрует транскрипты подзадач. А `<codex_internal_context source="goal">` добавляется самой системой, поэтому остаётся в восстановленном контексте, но никогда не считается ходом, который напечатали вы.

([한국어](./README-CODEX.ko.md) · [日本語](./README-CODEX.ja.md) · [简体中文](./README-CODEX.zh-Hans.md)).
`usage-view`, `report-limit` и `setup-statusline` пока остаются только в Claude Code.

## ✂️ Функция 4: /setup-git-lite — Обрезка встроенных инструкций git CC

**Мы прочитали исходный код Claude Code. Мы обнаружили 2 200 скрытых токенов, вставляемых в каждую сессию, за которые вы молча платите.**

### Открытие

12.04.2026 [проблема на GitHub](https://github.com/anthropics/claude-code/issues/47107) показала, что встроенная настройка `includeGitInstructions` Claude Code молча сжигает токены в каждой сессии. Независимое воспроизведение через [этот gist (spilist)](https://gist.github.com/spilist/b0db92a859192f5ec6199d3f35a81b98) подтвердило цифры: **+6 031 токен в записях кэша** на сессию после каждого git commit, **+1 690 токенов в чтениях кэша** при каждом вызове API.

### Анализ исходного кода CC — куда уходят токены

Мы отследили токены до двух независимых точек вставки в исходном коде Claude Code (v2.1.88):

**1. Снимок `gitStatus` (~500 ток) — системный запрос**
- `context.ts:36-111` `getGitStatus()` собирает ветку + основную ветку + user.name + полный статус (до 2000 символов) + **последние 5 коммитов**
- Объединяется и добавляется в системный запрос через `appendSystemContext` (`utils/api.ts:437`)
- Каждый новый коммит, каждый новый изменённый файл, каждое переключение ветки меняет текст → инвалидация кэша по префиксу

**2. Инструкции рабочего процесса Commit/PR (~1 700 ток) — описание инструмента Bash**
- `tools/BashTool/prompt.ts:53` добавляет 60+ строк протокола безопасности, пошаговых процедур коммита, примеров HEREDOC и шаблонов создания PR к описанию инструмента `Bash`
- Кэшируется вместе с системным запросом, но передаётся как параметр `tools[]`

### Почему это дорого

Структура кэша (`utils/api.ts:321` `splitSysPromptPrefix`) имеет три пути в зависимости от наличия активных инструментов MCP:

- **Путь A** (MCP активен — большинство пользователей): `gitStatus` находится внутри блока `cacheScope: 'org'`. Любое изменение → весь блок повторно кэшируется при следующем запуске сессии → промах `cache_create` на 6К ток.
- **Путь B** (без MCP): `gitStatus` идёт в динамический блок `cacheScope: null`, что означает повторную отправку как свежих `input_tokens` при каждом вызове API — без промаха кэша, но и без экономии на кэше.
- **Путь C** (сторонний провайдер / экспериментальные бета-версии отключены): то же, что Путь A.

В типичных интерактивных сессиях инструкции commit/PR (1,7К ток) накапливаются **при каждом вызове API** через `cache_read`. За 100-вызовную сессию по ценам Opus 4.7 это примерно **$0,08 за сессию** только за инструкции, которые обучение Claude уже в основном покрывает.

### Как super-token-saver это решает

`/setup-git-lite` отключает нативный путь и внедряет **куратированную замену на 280 токенов** через хук SessionStart. Мы оставили ровно то, что переопределяет поведение Claude по умолчанию (правила безопасности), и убрали всё, что Claude уже знает из обучения (пошаговые рабочие процессы, шаблоны PR, паттерны использования gh).

**Сохранено — 11 критических правил переопределения** (те, что переключают обычную отзывчивость Claude в осторожность):
- Никогда не коммитить/пушить/изменять/создавать PR/теги/слияния без явного запроса пользователя
- Никогда не пропускать хуки, force-push в main/master, выполнять деструктивные операции, изменять git config
- Никогда не коммитить файлы, соответствующие `.env`, `credentials`, `*.pem`, `secret.*`
- Избегать `git add -A` / `git add .`
- HEREDOC для многострочных сообщений коммита + трейлер `Co-Authored-By: Claude`
- Никогда не использовать интерактивные флаги (-i), без пустых коммитов
- Если хук pre-commit не удался → создать НОВЫЙ коммит (не `--amend`)

**Убрано** — пошаговый рабочий процесс коммита (3 шага), пошаговый рабочий процесс PR (3 шага), шаблон заголовка/тела PR, ссылки на команды `gh`, предупреждение о флаге `-uall`, предупреждение о `--no-edit` с rebase, ограничение `NEVER use TodoWrite or Agent tools during commit`. Это вербозность рабочего процесса, которую Claude правильно составляет только на основе обучения.

**Добавлено** — компактная строка состояния git: ветка + короткий SHA HEAD + тема + текущий статус (до 20 изменённых файлов, иначе счётчик). Без списка недавних коммитов (Claude может запустить `git log` по запросу).

### Ожидаемая экономия (цены Opus 4.7, $25/MTok вывод, $5/MTok ввод, $0,50/MTok чтение кэша)

| Элемент | Оригинал | С setup-git-lite | Сэкономлено |
| ------- | -------- | ----------------- | ----------- |
| Загрузка системного запроса (при новой сессии) | ~2 200 ток cache_create | ~280 ток cache_create | ~1 920 ток |
| Повторные вызовы в той же сессии | ~1 700 ток cache_read/вызов | ~280 ток cache_read/вызов | ~1 420 ток/вызов |
| 100-вызовная сессия (Opus 4.7) | — | — | **~$0,11 сэкономлено** |
| 20 сессий/день × 22 рабочих дня | — | — | **~$48 сэкономлено/мес** |

### Использование

```bash
/setup-git-lite status     # Диагностика только для чтения — текущее состояние + что изменится
/setup-git-lite install    # Отключить CC native + включить наш минимальный хук
/setup-git-lite revert     # Восстановить значения по умолчанию (агрессивно; см. ниже)
/setup-git-lite dismiss-banner    # Скрыть периодическую рекомендацию
/setup-git-lite undismiss-banner  # Снова включить подсказку
/setup-git-lite help       # Полное использование
```

### Семантика установки

`install` изменяет **два** места для надёжности:

1. `~/.claude/settings.json` — добавляет `"includeGitInstructions": false`
2. Профиль оболочки (`~/.zshrc`, `~/.bashrc` и т.д.) — добавляет маркерный блок, экспортирующий `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1`

Любого одного достаточно для отключения CC native; мы устанавливаем оба, чтобы переопределение среды случайно не повторно включило нативное поведение. Изменение оболочки вступает в силу только в новых оболочках.

### Семантика отмены — агрессивная

`revert` **удаляет ВСЕ экспорты `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS` из вашего профиля оболочки**, включая те, что вы могли добавить вручную до установки этого навыка. Это намеренно — вы запустили `revert`, так что мы восстанавливаем чистые значения по умолчанию. Мы всегда создаём резервную копию профиля оболочки с временной меткой.

Если вам нужна переменная среды по несвязанным причинам, запишите её до запуска `revert` и добавьте снова после.

### Перед удалением super-token-saver

**Сначала запустите `/setup-git-lite revert`**, иначе у вас останется `includeGitInstructions: false` в settings.json, но без замены хука (Claude вообще не получает инструкций по git). В Claude Code в настоящее время нет хука жизненного цикла удаления плагина, поэтому мы не можем автоматизировать это.

### Компромиссы

Что вы теряете (и почему это обычно нормально):
- Claude больше не получает предварительно вычисленный `git status` / `git log -n 5` при запуске сессии. Если вы спросите «что изменилось?» в новой сессии, Claude выполнит эти команды самостоятельно (один дополнительный вызов инструмента, ~300 ток).
- Claude больше не видит канонические 3-шаговые процедуры коммита CC. В наших тестах на сотнях потоков коммитов знания уровня обучения справляются с критическими случаями (форматирование HEREDOC, без `--amend`, без force-push), потому что мы сохраняем их как явные правила.
- Шаблон тела PR (`## Summary` + `## Test plan`) не вставляется. Если вам важен именно этот формат, поместите его в CLAUDE.md вашего проекта.

### Баннер рекомендации

Когда нативные инструкции git CC всё ещё активны на вашей машине, super-token-saver показывает однопараграфную подсказку при запуске сессии **~20% времени** (плюс в выводах `/usage-view` и `/report-limit`). Скройте навсегда с помощью `/setup-git-lite dismiss-banner`.

## 🛡️ Функция 5: Token Guardian

**Сообщает вам в момент, когда истечение кэша обходится вам в деньги. По вашему запросу может заблокировать повторную отправку на $9.**

TTL кэша запросов Claude Code составляет 1 час. Отойдите дольше — и кэш истечёт. Ваше следующее сообщение повторно отправит весь контекст по полной цене. При 900К токенов это $9 за один раз.

Token Guardian запоминает, когда пришёл последний ответ. Если прошло более 3 590 секунд (TTL минус буфер 10 секунд), он может вмешаться. **По умолчанию он отключён — из-за Remote Control.** Блокирующее сообщение хука рендерится локально как системное сообщение, которое удалённый клиент никогда не получает, поэтому удалённый пользователь видел, как запрос просто исчезал без объяснений. Вместо того чтобы поставлять защиту, которая ведёт себя по-разному в зависимости от того, где вы находитесь, мы её отключили. Когда Remote Control начнёт пересылать сообщения хуков, значение по умолчанию снова включится. А до тех пор включите её сами — одним из двух режимов.

```
export CC_TOKEN_SAVER_CACHE_GUARD=warn    # Claude упоминает об истечении в первой строке
export CC_TOKEN_SAVER_CACHE_GUARD=block   # запрос отклоняется один раз с сообщением ниже
```

В режиме `warn` запрос проходит, а Claude открывает ответ одной строкой о том, что кэш истёк, что этот ход оплатил весь контекст целиком, и что после перерыва в час и более более дешёвый путь назад — `/clear` → `/s-continue`. Это сообщение действительно доходит до удалённого клиента, потому что ответ Claude пересылается, даже когда сообщения хуков — нет.

В режиме `block` запрос отклоняется один раз с сообщением ниже. Отправьте его снова — и он пройдёт. Используйте его в локальном терминале, когда нужна жёсткая остановка.

```
🚨 Cache expired (68m 23s idle)

The prompt cache has expired. Continuing will resend the full context.
Cost may increase significantly.

👉 /context — Check current context usage before deciding
👉 /clear → /s-continue — Reset, then restore previous context (recommended, cheapest)
👉 Re-send — Continue as-is (full re-cache cost incurred)
```

Блокирующее сообщение отображается на 23 языках, выбранных по локали вашей ОС, и срабатывает один раз за период простоя.

**Фоновые агенты никогда не блокируются.** Проверку проходят только запросы, введённые человеком вручную. Отчёты о завершении от фоновых агентов и задач — которые в наши дни часто приходят спустя более часа после запуска — проходят напрямую. Результат долго работающего агента никогда не задерживается и не теряется.

**Результат:** в режиме предупреждения вы всегда знаете, когда произошла повторная отправка на $9 и почему. В режиме block этого вообще не происходит: каждый перехваченный случай истечения кэша экономит $9, а при одном перехвате в день это $270/мес чистых потерь устранено.

> **На тарифе с оплатой по факту это бьёт сильнее.** Подписчик Max Plan теряет $9 в рамках буфера $200. Вы теряете $9 реальных денег — молча, каждый раз, когда отходите. Режим block останавливает это каждый раз.

## 💡 Как на самом деле работает кэш (и почему большинство пользователей тратят 40%+ впустую)

Claude Code отправляет всю историю разговора в модель при каждом вызове API. «Вызов API» не означает «одно сообщение, которое вы ввели». Один запрос запускает внутренние вызовы инструментов — Grep, Read, Edit, Write — и каждый из них является отдельным вызовом API. Один запрос легко может вызвать 10+ вызовов API.

Кэш запросов снижает эту стоимость на 90%. Но кэш имеет срок жизни.

|                     | Main Session                               | SubTask                                    |
| ------------------- | ------------------------------------------ | ------------------------------------------ |
| TTL кэша            | 1 час (ephemeral_1h)                       | 5 мин                                      |
| Запись в кэш        | ＄10/MTok                                   | ＄6.25/MTok                                 |
| Чтение кэша         | ＄0.50/MTok                                 | ＄0.50/MTok                                 |
| При истечении кэша  | Полный контекст повторно отправляется по полной цене | Малое влияние (контекст небольшой) |

Даже при живом кэше затраты накапливаются. Вот крайний сценарий для демонстрации разницы.

### Сценарий: Полный рабочий день (3ч утро → 2ч обед/совещание → 3ч послеполудень)

Условия: цены Opus 4, 1 запрос в минуту, ~5 вызовов API на запрос (~300 вызовов/час).

#### ❌ Без super-token-saver

Большая часть работы происходит в Main session. Контекст быстро растёт.

| Фаза          | Ситуация                            | Размер контекста               | Стоимость                                 |
| ------------- | ----------------------------------- | ------------------------------ | ----------------------------------------- |
| Утро 3ч       | Работа (в основном в Main)          | 100К → 600К (ср. 350К)        | 900 вызовов × 350К × ＄0.50/M = ＄157.50   |
| Обед/совещ.   | Отсутствие 2 часа                   | —                              | —                                         |
| Возвращение   | Кэш истёк → полная повторная отправка | 600К по полной цене          | 600К × ＄5/M + 600К × ＄10/M = ＄9          |
| Возвращение   | /compact (резюме)                   | 600К → отправка в LLM         | 600К × ＄0.50/M + вывод резюме = ~＄1.50   |
| Послеполудень 3ч | Работа продолжается (контекст снова растёт) | 100К → 600К (ср. 350К) | 900 вызовов × 350К × ＄0.50/M = ＄157.50 |
|               | Итого                               |                                | ~＄326                                     |

> При таком уровне использования вы, скорее всего, достигнете лимита 5-часового окна. **Затраты плохи, но реальная проблема — ваша работа полностью останавливается. Это именно тот момент, когда Claude Code гаснет.**

#### ✅ С super-token-saver

Тяжёлая работа делегируется в SubTask. Main обрабатывает только проектирование/решения.

| Фаза          | Ситуация                                        | Размер контекста                   | Стоимость                           |
| ------------- | ----------------------------------------------- | ---------------------------------- | ----------------------------------- |
| Утро 3ч       | Работа (Main: проектирование, SubTask: реализация) | Main 100К → 300К (ср. 200К)     | 900 вызовов × 200К × ＄0.50/M = ＄90 |
| Обед/совещ.   | Отсутствие 2 часа                               | —                                  | —                                   |
| Возвращение   | ⚡ Token Guardian (режим block) → /clear + /s-continue | —                                  | ＄0 (без вызовов LLM)               |
| Послеполудень 3ч | Работа продолжается                           | Main 100К → 300К (ср. 200К)       | 900 вызовов × 200К × ＄0.50/M = ＄90 |
|               | Итого                                           |                                    | ~＄180                               |

#### 💰 Результат

> **＄326 → ＄180. ＄146 сэкономлено в день. Снижение затрат на 45%.**
>
> **Max Plan:** Меньше токенов = вы не достигаете лимита. Ваша работа не останавливается. В этом и состоит реальное отличие.
>
> **API с оплатой по факту:** ＄146/день × 22 рабочих дня = **＄3 200/мес прямо с вашего счёта.** Тяжёлый месяц без этого плагина превышает ＄7 000. С ним — ниже ＄4 000. При том же объёме работы.

### Где вступает super-token-saver

```
[Запуск сессии]
    │
    ├─ Session Architect → Автоматически внедряет паттерн делегирования SubTask
    │                       Удерживает Main контекст ниже 250К
    │
[Работа]
    │
    ├─ Status Line → Мониторинг стоимости/контекста/лимита в реальном времени
    │                  Мгновенное оповещение при входе в зону предупреждения
    │
[Простой 1+ час]
    │
    ├─ Token Guardian → Обнаруживает истечение кэша, предупреждает (или блокирует в режиме block)
    │
[Перезапуск сессии]
    │
    └─ /s-continue → Восстанавливает предыдущий контекст без затрат (без вызовов LLM)
```

## 🔧 Установка из источника и настройка

```bash
git clone https://github.com/ww-w-ai/super-token-saver.git
/plugin marketplace add /path/to/super-token-saver
/plugin install super-token-saver@ww-w-ai
```

super-token-saver полностью с открытым исходным кодом (Apache-2.0). Чистый JavaScript + Bash — без скомпилированных бинарных файлов, без внешних вызовов API, без телеметрии. Каждая строка доступна для аудита. Каждое утверждение в этом README соответствует конкретному файлу, который вы можете прочитать.

- **hooks/** — Изменить порог истечения кэша, настроить предупреждающие сообщения, изменить правила архитектуры сессий
- **scripts/** — Логика анализа, конструктор отчётов, форматирование строки статуса
- **skills/** — Как работают /s-continue и /usage-view, шаблоны запросов
- **locales/** — Добавить/редактировать переводы, добавить новые языки
- **skills/usage-view/** — Изменения дизайна UI/UX панели

Сделайте его своим. Форкните, экспериментируйте и отправьте PR, если найдёте что-то лучше.

## ⚖️ Что этот плагин стоит вам

Плагин внедряет контекст при запуске сессии. Вот точно сколько:

| Внедрение | Когда | Токены | Назначение |
| --------- | ----- | ------ | ---------- |
| Session Architect | SessionStart (один раз) | ~1 100 | Стратегия делегирования SubTask + правила Concise Mode |
| Git-контекст (если git-lite включён) | SessionStart (один раз) | ~280 | Заменяет нативные ~2 200 ток инструкции git CC |
| Предупреждение об истечении кэша | При простое > 59м (один раз) | ~200 | Отмечает дорогостоящую повторную отправку, показывает более дешёвый путь |
| Строка статуса | При каждом вызове API | 0 | Отображается в строке статуса терминала, не в контексте разговора |

**Чистые накладные расходы на сессию: ~1 400 токенов (одноразово, кэшируется после первого вызова).**

По ценам Opus ($0,50/MTok чтение кэша) это **$0,0007 за вызов API** — менее одной десятой цента. За 100-вызовную сессию: $0,07.

Если git-lite включён, плагин **экономит** ~1 920 токенов на сессию (заменяет 2 200 на 280). Чистый эффект отрицательный — плагин потребляет меньше, чем убирает.

**Для пользователей API по факту:** при расходах $3 000/мес, накладные расходы плагина составляют менее $2/мес. Одна сэкономленная от истечения кэша $9 повторная отправка в неделю окупает годовые накладные расходы за один перехват.

## 💡 Советы

### Понимание кэша — и вы увидите, куда уходят деньги

- **1 запрос ≠ 1 вызов API.** Каждый раз, когда Claude вызывает Grep, Read или Edit, весь контекст повторно отправляется. Один запрос легко запускает 10+ вызовов API. Пишите чёткие запросы, чтобы сократить ненужные вызовы инструментов и снизить затраты.
- **Таймер кэша сбрасывается с последнего вызова API, а не вашего последнего запроса.** Продолжайте работать — и кэш никогда не истечёт. Опасность — в отходе. Token Guardian сообщает вам, когда это произошло, а в режиме `block` останавливает запрос один раз, так что вы можете выбрать: сбросить контекст или продолжить как есть.
- **Размер контекста = множитель затрат.** Тот же вызов API при 200К против 800К стоит в 4 раза дороже. Когда строка статуса [CTX] пересекает 35% (🟡), это сигнал делегировать больше в SubTask.

### Привычки, снижающие затраты

- **Держите CLAUDE.md лаконичным.** Он загружается в системный запрос при каждом вызове API. Каждая строка стоит денег.
- **Делегируйте тяжёлую работу в SubTask.** Генерация кода, редактирование нескольких файлов, запуск тестов не принадлежат Main. SubTask имеют меньший контекст и более дешёвый уровень кэша.
- **Отходите на 1+ часа?** `/clear` → вернитесь → `/s-continue`. Контекст восстановлен за $0.
- **[5H] выше 70% (🟡)?** Замедлитесь. Переключитесь на лёгкие задачи проверки или увеличьте делегирование SubTask для уменьшения количества вызовов API из Main.
- **Используйте `/btw` для побочных вопросов.** Они не входят в историю разговора, поэтому контекст остаётся лаконичным.

### API с оплатой по факту: самые важные привычки

Всё вышеизложенное применимо, плюс эти приоритеты, специфичные для API:

- **Следите за [CTX] как за спидометром.** Лимит вас не остановит — но контекст на 500К+ означает, что каждый вызов API стоит в 2-3 раза больше, чем должен. `/clear` → `/s-continue` бесплатны и сбрасывают ваш множитель затрат до базового.
- **Запускайте `/usage-view` еженедельно.** У пользователей Max Plan есть естественный момент «ой» при достижении лимита. У вас нет — затраты растут молча. Панель — ваша система раннего предупреждения.
- **Установите мысленный дневной бюджет.** Без ограничения дни на $200 случаются незаметно. Индикатор RUN строки статуса делает стоимость за ход видимой. Если один ход превышает $1 (🔴), ваш контекст слишком велик.
